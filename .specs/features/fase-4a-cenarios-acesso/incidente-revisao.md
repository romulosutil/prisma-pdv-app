# Incidente na limpeza da primeira revisão

Em30/10/2026, a limpeza do primeiro sensor usou remoção forçada de worktree temporário com junction de node_modules ainda presente. A travessia dos links de workspaces atingiu apps/api, apps/mobile e packages/shared da árvore principal. Esse sensor foi invalidado. A abordagem contrariou a orientação explícita de desvincular links antes de limpar; não será repetida.

O revisor restaurou os arquivos rastreados desses três workspaces que estavam limpos no snapshot inicial. O README modificado pelo usuário foi preservado. Dependências e arquivos ignorados também foram atingidos: foi confirmada a remoção de apps/api/.env.resend.local e apps/mobile/.expo. A instalação de dependências iniciada pelo revisor foi interrompida; o gestor executou npm ci pelo lockfile até concluir (696 pacotes). O usuário resalvou o arquivo de ambiente ainda aberto no editor. Nenhuma chave foi solicitada/lida no chat ou versionada. Não há inventário prévio suficiente para afirmar recuperação de todos os arquivos ignorados; os caches de desenvolvimento são regenerados pelo servidor.

O banco Docker não foi removido/parado: produto, venda e caixa de homologação foram conferidos antes/depois e permaneceram. A venda concluída25 está vinculada ao caixa; o rascunho local com parcela10/saldo15 reapareceu na instalação A após reiniciar API/Metro e recarregar a página. A configuração foi validada com o parser sem imprimir valores; SMTP9/9 e tipos API/mobile/shared passaram após recuperação. Status tracked voltou somente ao README preexistente antes dos novos relatórios. Não houve alteração na VPS, produção ou cobranças reais.

Uma revisão nova usou falhas apenas em memória, por plugin de compilação de testes com configuração temporária. Não criou worktrees, junctions ou cópias de node_modules, não removeu diretórios recursivamente nem alterou fontes. Cinco falhas comportamentais foram detectadas com asserções e os hashes dos arquivos-alvo permaneceram iguais. Evidências e limites em validation.md. Política para próximos sensores: nenhuma remoção de worktree/link; usar transformação em memória e limpar somente arquivos temporários individuais com caminho validado.
